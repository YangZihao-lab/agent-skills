# Kala-Agent 示例映射

## 当前窗口配置

### 战略综合窗口

- **主要层级：法**
- **兼容宽度：多术，并要求主动比较多法**
- 处理对象：不同项目路线背后的思维方式
- 例如：
  - 证据审计优先
  - 完整案例学习优先
  - 快速产品原型优先
  - 评测驱动优先
- 它必须比较这些法，而不能默认“证据越严格越好”。
- **上浮复核**：持续回到“培养实际占星分析能力”这一最初目的，检查当前法是否已经成为新的执着。

### 项目设计窗口

- **主要层级：术**
- **兼容宽度：多器**
- 处理对象：在“培养 AI 占星分析能力”这一领域内，课程、案例、Calc、评测怎样构成方法论
- 它可以决定：
  - 完整案例提取方法
  - 来源主张如何作为证据
  - 验证集和盲测怎样使用
- 它不能自行改变最终目标。
- **上浮复核**：检查当前课程学习方法论是否仍符合用户确认的战略，以及是否存在完全不同、成本更低的术。

### 执行与方法窗口

- **主要层级：器**
- **兼容宽度：多事、多器比较**
- 处理对象：
  - 双遍提取流程
  - 校验器
  - 任务模板
  - Control/Codex 指令
- 它可以优化这些器，但不能宣布“双遍提取就是项目最终方法论”。
- **上浮复核**：当连续修补器、增加协议或复杂度上升时，检查这些工作是否仍对课程学习方法论有可见收益。

### Codex

- **主要层级：事 / 物**
- 按批准的方法修改代码和文件、运行测试。
- 发现任务需要改器时必须上报。
- **上浮复核**：即使只负责代码，也要知道当前修改服务哪个器和术；若任务开始扩张为新工具或新方法论，不自行扩张。

## Codex 上浮复核示例

### 当前任务

修复 `verify-acceptance` 的一个绑定错误。

### 正常执行

Codex 可以：

- 修复明确错误；
- 增加必要测试；
- 报告修改和验证结果。

### 应当向上看

如果执行中发现：

- 修复需要再建立一套索引；
- 同类绑定问题已经连续出现；
- 继续加固只提高审计复杂度；
- 没有证据表明它改善 AI 学习完整案例的能力；

Codex 应报告：

> 当前修复可以在批准范围内完成，但继续扩展验收体系可能已属于器或术的重新设计。建议上级判断是否继续，不在本任务中自动扩张。

Codex 可以提出这个判断，但不能自行废弃双遍协议或改做完整案例系统。

## 双轮高价值收敛的实际示例

下面根据实际工作窗口的总结说明如何区分当前周期与下一目标：

### convergence_target

完成当前 Raja Yoga 课程材料包的主体合并，并修补最影响合并质量的已知缺口。

### 第一轮：主干建设

```text
12 个课程包 + 初次总合并
→ 主体链路走通
→ 发现白羊、金牛两处深度不足
```

### 第二轮：高影响修补

```text
P-RY06 + P-RY07 + FINAL_V2
→ 只修补影响最大的两个缺口
```

### 两轮后分类

- 不影响当前合并成立的小问题：`ACCEPT_RESIDUAL`；
- 当前收益不足的补充工作：`DEFER`；
- 验证 Agent 是否能够运用课程知识：`NEXT_OBJECTIVE`，不是当前周期的“剩余 4%”。

因此，不应重做全部合并，也不应以“还有运用测试”为理由继续当前合并周期。当前合法动作是：

```text
CLOSE_CURRENT_CYCLE
```

这只表示当前材料合并目标已经收敛，不表示 Kala-Agent 的分析能力已经完成。

## 来自实际断舍离的证明边界

一次真实整理进一步证明：

```text
466 课文件生成成功
≠ 466 个时间轴质量都可靠
≠ 老师的分析过程已经提取
≠ 教材已经完成
≠ Agent 已经学会运用
```

同样：

- 把 466 课放进同一个目录，在“文件与视频一一对应”的物层上可以成立，但在用户理解七门课程的事/器层上可能错误；目录应镜像用户天然理解的课程结构。
- 自动关键帧、视觉索引、质量统计、失败重试和哈希清单可以在一次试验中有用，但没有长期消费者时属于一次性产物。
- 一套教材已经生成，不代表它达到了可学习质量；极度压缩、丢失连续观察和否决条件的教材可以删除并从更上游材料重建。
- 已删除路径只说明历史上做过，不构成未来恢复理由；是否重建必须重新证明当前消费者、上游不足和用户授权。

因此，任何任务开工前都应明确：

```text
最初目标
→ 当前层级
→ 最短主链
→ 只允许留下什么
→ 最多能证明什么
→ 何时停止
```

当方向正确但结构已经膨胀时，应执行 `REQUEST_RAZOR_AUDIT`，而不是在分层治理中再增加一套整理系统。

## Kala-Agent 曾发生的层级替代

```text
物：JSON、SHA、artifact index 完整
        ↓ 被误当成
事：一次来源提取任务成功
        ↓ 被误当成
器：双遍与合并工具可靠
        ↓ 被误当成
术：课程知识提取方法论正确
        ↓ 被误当成
法：这条路线能够培养 AI 分析能力
```

正确判断应是：

> 低层成功只能证明低层问题得到解决；是否服务上层目标，必须用上层验收标准重新检查。

## 每个窗口都应上浮，而不是只等待战略窗口

```text
Codex：事 / 物 → 回看器与术
执行窗口：器 → 回看术
项目设计：术 → 回看法和最终目的
战略窗口：法 → 回看用户最初目的，并检查是否需要道式复盘
```

分层不是让下层停止思考，而是让所有窗口保持更高视野，同时不越权行动。

## 何时触发道式复盘

- 双遍协议不断加固，但完整案例学习仍未开始
- 项目默认只能“继续完善”，没有暂停或废弃选项
- 所有窗口都继承同一份 AI 写出的文档并相互证明
- 用户多次询问方向，但收到的只是低层进度
- 每个窗口都能解释本层工作，却没有任何窗口回到最初目的

此时不立即设计下一项任务，而先允许：

- 暂停来源批处理
- 换成完整案例实验
- 保留现有器但不继续扩张
- 重新由用户裁决项目方法
