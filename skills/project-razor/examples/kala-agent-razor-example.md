# Kala-Knowledge-Lab / Kala-Agent 断舍离实例

> 本例来自一次真实七轮清理的复盘，用于提炼通用规则；执行任何新清理仍须读取项目当前状态。

## 清理前的问题

来源处理、自动语义提取、训练、测评、审计、协议、教材、抽帧和环境混在一起。文件很多，但用户和 AI 都难以判断：

- 哪些是上游来源；
- 哪些只是复核入口；
- 哪些是真正教材；
- 哪些测评可以证明能力；
- 哪些只是一次性试验垃圾；
- 哪些环境需要长期保留，哪些只是一次性运行物。

## 收敛后的主链

```text
外部原视频与文本
        ↓
review.html + stable_ts.json
        ↓
逐课重建老师的分析过程
        ↓
真正教材
        ↓
Kala-Agent 运用与验证
```

## 七类删除

1. 偏离目标的来源层、Schema、自动语义提取、catalog 和测试。
2. 不成立的训练与测评：长窗口、54 条纠错、冻结答卷和排列组合。
3. Raja Yoga 之后六门质量不足的压缩教材及 V0—V5。
4. 约 1,780 个 pilot 派生物，包括 1,528 张自动关键帧、视觉索引、失败重试和质量统计。
5. Raja Yoga 多窗口波次目录、中间合并版本和完成任务指令。
6. 清理过程制造的 admin、回滚清单、哈希审计、空占位和旧脚本。
7. 两个只服务一次生成任务、无持续消费者且可可靠重建的环境，以及一次性工作目录与缓存。

## 明确保留

- 外部原视频和原始/cleaned 文本；
- 每课 `review.html` 与 `stable_ts.json`；
- Raja Yoga 14 个详细包和累计教材；
- `local/sources/`；
- 尚未完成的公众号来源目录；
- 仍被长期使用的模型缓存、工具链或环境，只要消费者、职责和退役条件明确。

## 环境删除的真正理由

本次删除两个约 5 GiB 的环境，不是因为“环境大”或“可重建”，而是因为：

- 它们只服务一次批量生成任务；
- 任务已经完成；
- 没有持续消费者；
- 重建来源明确；
- 保留不会改善当前主链。

若某环境会被持续用于课程复核、Agent 开发或模型运行，即使体积大、理论上可重建，也可以 `KEEP_ACTIVE`。

## 最小生成核

这次清理后保留的生成核不是一份巨大的总索引，而是：

```text
外部原视频和文本
+ review.html / stable_ts.json 复核入口
+ 逐课分析方法与边界
+ 14 个详细包和累计教材
+ 当前状态与主链说明
```

未来材料应从这些上游和规则重新生成，而不是复活旧压缩教材、旧测评或复杂来源流水线。

## 最重要的证明边界

```text
466 课 review.html + stable_ts.json 齐全
≠ 466 个时间轴质量全部可靠
≠ 老师分析过程已经提取
≠ 七门课程教材已经完成
≠ Agent 已经学会
```

旧分数、54 条纠错、长窗口和 V0—V5 也不得重新包装成能力证据。

## 认知拓扑教训

一度把 466 课放进同一目录。在“每个视频有对应文件”的物层上正确，但不符合用户按七门课程理解项目的自然结构。

最终目录镜像七门原课程。说明项目结构必须同时服务机器和人的认知。

## archive 教训

把垃圾全部搬进 archive，再为 archive 建索引，并不叫简化。只有确有审计或复现价值的历史才归档；否则删除。

## 清理系统也要删除

清理完成后，逐文件清单、relocation manifest、哈希账本、回滚快照、临时脚本、一次性环境和日志全部退出活跃结构。

最终只保留一份“删了什么、为什么删、能否重建”的人话说明；当前状态仍由唯一状态文件定义。

## 动作前剃刀示例

准备再增加一个课程 catalog 前，先问：

- **需要吗**：现有目录和状态文件无法表达什么？
- **替代呢**：能否在现有唯一入口增加一个小节，而不是新建 catalog？
- **归宿呢**：谁会长期读取？何时退役？
- **生成核呢**：是不是可以保留上游与规则，按需生成视图？
- **认知成本呢**：未来 AI 是否又要比较两套入口？

若没有明确答案，应 `REJECT_ADDITION` 或 `USE_EXISTING`，而不是先建再说。

## DO_NOT_RECREATE

以下即使技术上可重建，也默认不应恢复：

- 低质量压缩教材；
- 无效测评和旧分数体系；
- 自动抽帧与视觉索引流水线；
- 复杂来源协议和多重 catalog；
- 没有长期消费者的审计、哈希和批处理管理层。

恢复必须重新证明当前消费者、最小必要范围和用户批准。
