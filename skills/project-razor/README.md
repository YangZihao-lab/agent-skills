# Project Razor v0.3

项目断舍离与剃刀 Skill。它现在不仅用于清理已经膨胀的项目，也作为长期默认开启的轻量护栏，在每次新增或长期保留结构前检查必要性、替代方案、生命周期和认知成本。

## v0.3 核心升级

- 新增隐式默认模式 `PRE_ACTION_RAZOR`；
- 所有新增前先问：真的需要吗、已有替代吗、最后如何处理；
- Project Razor 改为允许隐式调用，但隐式模式永远只读、不自动清理、不输出无价值长报告；
- 长期反复使用、具有明确消费者和退役条件的环境与工具链可以 `KEEP_ACTIVE`；
- 体积大或可重建不再构成充分删除理由；
- 加入“简洁优雅”设计偏好：同等满足要求时，优先更少概念、更少入口、更强组合性的方案；
- 加入“生成核”原则：保留可信上游、元规则、稳定接口和必要测试，按需推导大量下层产物；
- 把人的认知预算视为正式成本，要求每个长期对象说明用户和 AI 需要多记住什么；
- 保留所有实际清理和恢复必须经过用户明确批准的边界。

## v0.2 核心升级

- 以“最短主链、当前消费者、上游来源、最大证明范围”判断活跃资格；
- 新增 `DO_NOT_RECREATE`，防止未来 AI 从旧文档自动复活失败路线；
- 明确 archive 不是垃圾桶；
- 增加认知拓扑检查；
- 新增 `FINALIZE_CLEANUP` 与 `RESTORE_REVIEW`；
- 大型清理只保留一份最小人话决策说明；
- 明确文件齐全、时间轴生成、教材写完和测评分数的证明上限。

## 默认行为

- 默认只读；
- 允许隐式调用；
- 隐式调用只执行轻量 `PRE_ACTION_RAZOR`；
- 如果检查不改变动作，可以静默通过；
- 不自动发起大型清理；
- 用户明确批准精确动作后，才允许移动、合并、归档、删除或恢复；
- 不把功能开发、方法论重设计与结构清理混在一起；
- 不删除上游来源、证据、许可证、迁移历史、用户保护材料和已批准的长期环境。

## 隐式日常习惯

在创建、安装或长期保留任何对象前，检查：

```text
NEED：真的需要吗？
ALTERNATIVE：已有替代吗？
DESTINATION：临时还是长期，最后如何退出？
GENERATIVE_CORE：能否只保留更小的生成核？
COGNITIVE_COST：未来用户和 AI 需要多记住什么？
```

隐式检查的合法结论：

- `USE_EXISTING`
- `CREATE_TEMPORARY`
- `CREATE_PERSISTENT`
- `REJECT_ADDITION`
- `ESCALATE`

## 显式调用

```text
$project-razor

对我准备新增的工具执行 PRE_ACTION_RAZOR：它真的需要吗、已有替代吗、应该临时还是长期保留、最后如何退出？
```

```text
$project-razor

执行 QUICK_RAZOR。先画出当前最短主链和最大证明范围，再指出最影响理解的五个复杂度来源。
```

```text
$project-razor

生成 CUT_PLAN，不修改。每项说明当前消费者、已有替代、生命周期、上游重建来源、证据价值和未来是否允许重建。
```

```text
$project-razor

执行 FINALIZE_CLEANUP：删除本次清理制造的临时 admin、清单、一次性环境和日志；保留已确认长期使用的环境和工具链。
```

## 与分层治理的关系

`layered-thinking-governance` 决定目标、层级、权限、最短主链、允许产物和证明上限；`project-razor` 在每个动作中检查是否真的需要新增，并在批准范围内把器、事、物层压到最小。刀不能自行改变项目方法论或战略。
