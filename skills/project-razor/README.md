# Project Razor v0.2

项目断舍离与剃刀 Skill，用于减少软件项目中的重复入口、多重真相源、历史包袱、一次性派生物和维护面。

## v0.2 核心升级

- 以“最短主链、当前消费者、上游来源、最大证明范围”判断活跃资格；
- 新增 `DO_NOT_RECREATE`，防止未来 AI 从旧文档自动复活失败路线；
- 明确 archive 不是垃圾桶；
- 增加认知拓扑检查：目录不仅机器可遍历，也要符合用户自然理解；
- 一次性脚本、环境、缓存、日志和清理 admin 默认在任务结束后删除；
- 新增 `FINALIZE_CLEANUP` 与 `RESTORE_REVIEW`；
- 大型清理只保留一份最小人话决策说明，不保留逐文件管理系统；
- 明确文件齐全、时间轴生成、教材写完和测评分数的证明上限。

## 默认行为

- 默认只读；
- 默认显式调用；
- 先审计和出计划；
- 用户明确批准精确动作后，才允许移动、合并、归档、删除或恢复；
- 不把功能开发、方法论重设计与结构清理混在一起；
- 不删除上游来源、证据、许可证、迁移历史和用户保护材料。

## 调用

```text
$project-razor

执行 QUICK_RAZOR。先画出当前最短主链和最大证明范围，再指出最影响理解的五个复杂度来源。
```

```text
$project-razor

生成 CUT_PLAN，不修改。每项说明当前消费者、上游重建来源、证据价值和未来是否允许重建。
```

```text
$project-razor

执行 FINALIZE_CLEANUP：删除本次清理制造的临时 admin、清单、环境和日志；只在确有必要时保留一份最小人话决策说明。
```

## 与分层治理的关系

`layered-thinking-governance` 决定目标、层级、权限、最短主链、允许产物和证明上限；`project-razor` 在批准范围内把器、事、物层压到最小。刀不能自行改变项目方法论或战略。
